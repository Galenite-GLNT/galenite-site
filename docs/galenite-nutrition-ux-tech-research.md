# Deep research: UX‑фичи и техрешения популярных трекеров питания и здоровья для Galenite

## Executive summary
- Рынок трекеров питания сходится к базовому UX-циклу: **быстрое добавление еды** (поиск/штрихкод/шаблоны) → **дневник по приёмам пищи** → **дневные агрегаты** (ккал + КБЖУ, иногда микроэлементы) → **цели и прогресс**.
- Продукты-лидеры выигрывают не редкими фичами, а скоростью базовых действий (2–3 тапа без тупиков).
- Для web/mobile web критичен гибридный сканер: `BarcodeDetector` → fallback на `@zxing/browser` → ручной ввод/поиск/создание продукта.
- Для базы продуктов приоритет open/free + RU-охват логично закрывать через OpenFoodFacts (API v2, большой каталог, русскоязычная витрина).
- Базовая архитектура для Galenite: **PWA + IndexedDB (offline-first)** + **Cloudflare Worker API** + **D1** + опционально **KV cache**.
- Данные питания/веса/сна должны обрабатываться как чувствительные health-data: explicit consent, минимизация, экспорт/удаление, доступ к камере только по действию пользователя.

## 1) UX-референсы и продуктовые паттерны

### 1.1 Что стоит перенести в Galenite (MVP)
1. Единая точка входа добавления: кнопка `+` с методами (поиск/скан/недавнее).
2. После выбора продукта — сразу экран порции/граммовки с live-пересчётом КБЖУ.
3. 4 стандартных meal-группы: `breakfast/lunch/dinner/snacks`.
4. Мгновенный путь сканера: скан → карточка продукта → добавить.
5. Обязательные fallback-сценарии сканера (не найдено, нет камеры, не поддерживается API).

### 1.2 Рекомендуемый flow добавления еды
`Add Food` → `Search/Scan` → `Product Modal (amount + meal + timestamp)` → `Add`

Требования к UX:
- Не держать пользователя в камере после распознавания.
- Не скрывать следующий шаг (всегда показывать CTA для продолжения).
- В любой точке должен быть безопасный выход к ручному поиску.

### 1.3 Must-have экраны/компоненты
- Dashboard cards: Calories, Protein, Fat, Carbs, Water, Sleep, Weight.
- Food Log: 4 секции по приёмам пищи + subtotal по каждой.
- Add Food modal: поиск + Recent/Favorites + Scan barcode.
- Product modal: per 100g + servings + meal selector + CTA.
- Sleep modal: start/end + auto duration.
- Water quick-add: +200/+250/+500 + custom.
- History view: навигация по дням.
- Редактирование и удаление записей из списков.

## 2) Техническая архитектура для web + mobile web

```mermaid
flowchart LR
 U[User: Mobile Web / Desktop Web] --> FE[PWA Frontend\nUI + State + IndexedDB]
 FE <--> API[Edge API\nCloudflare Worker]
 API <--> DB[(D1 SQL Database)]
 API <--> KV[(KV Cache)]
 API <--> EXT[External Nutrition APIs\nOpenFoodFacts (primary)]
 FE <--> CAM[Camera / Barcode Scanner\nBarcodeDetector or JS fallback]
```

### 2.1 Почему такой стек
- IndexedDB даёт устойчивый offline-режим и быстрый локальный журнал дня.
- Worker упрощает CORS, ключи, rate-limit, проксирование внешних API.
- D1 закрывает серверное хранение логов и синхронизацию между устройствами.
- KV выгоден для горячего кеша (`barcode -> product`, популярные поисковые запросы).

### 2.2 Синхронизация (offline-first)
- Все изменения пишутся в локальный outbox.
- При сети отправляется batch на Worker API.
- Конфликты: `last-write-wins` + журнал изменений.
- Периодический sync-commit и экспорт для защиты от browser eviction.

## 3) Сканер штрихкодов: рекомендованный гибрид

### 3.1 Приоритетная цепочка
1. `BarcodeDetector` (если доступен и поддерживает нужные форматы)
2. `@zxing/browser` (JS fallback)
3. Ручной ввод штрихкода / текстовый поиск / создание продукта

### 3.2 UX-правила сканера
- Полноэкранный оверлей с viewfinder и явным текстом подсказки.
- Кнопки: закрыть, фонарик (если поддерживается), ручной ввод.
- После успешного чтения: сразу закрывать камеру и открывать Product Modal.

## 4) Источник данных о продуктах

### 4.1 Базовый выбор
- OpenFoodFacts как primary-источник для MVP:
  - barcode lookup через API v2,
  - большой охват,
  - RU-витрина,
  - open-data модель.

### 4.2 Что учесть юридически
- Данные: ODbL (атрибуция и share-alike для производных баз).
- Изображения: отдельные права/условия.
- Нужно хранить source/attribution на уровне product entity.

## 5) Данные и доменные модели

### 5.1 Базовые сущности
- User profile (locale/timezone/units/рост/пол/активность)
- Goals (ккал, КБЖУ, вода, сон, целевой вес)
- Product (source-id, barcode, nutrientsPer100g, servings)
- FoodEntry (meal, amount, computed macros)
- WaterEntry, SleepEntry(start/end), WeightEntry
- DayLog (агрегаты + progress к целям)

### 5.2 Ключевые вычисления
- Пересчёт КБЖУ: `k = grams/100`, далее умножение per100g.
- Энергия по макросам (проверка пользовательского ввода):
  `kcal ≈ 4*protein + 9*fat + 4*carbs`.
- Sleep через полночь:
  - если `end <= start`, добавить 1 день к `end`.
- Progress: `min(value/goal, 1.0)`.

## 6) Privacy и комплаенс
- Явный opt-in на обработку health-данных на первом запуске.
- Отдельное объяснение для доступа к камере (только по кнопке “Сканировать”).
- Экспорт данных (JSON/CSV) и удаление аккаунта в явном пользовательском флоу.
- Минимизация данных: не хранить лишние изображения/сырые медиа без необходимости.
- HTTPS-only, безопасное хранение сессий и короткоживущие токены.

## 8) Acceptance criteria (готово/не готово)

### Питание
- В UI всегда видны ккал + Б/Ж/У (день и meal).
- FoodEntry хранит `amount` и `computed`.
- Используются 4 meal-группы.

### Добавление еды
- Flow: Add Food → Search/Scan → Product Modal → Add.
- Live-пересчёт при изменении граммовки.
- Есть Recent/Favorites.

### Штрихкод
- На mobile web есть кнопка “Сканировать”.
- После скана сразу открывается Product Modal.
- Реализована fallback-цепочка native → zxing → manual.
- Для “не найдено” есть действия: поиск/создать/ввести вручную.

### Сон/вода/вес
- Сон хранится как start/end с автодлительностью.
- Вода имеет quick-add и историю.
- Вес имеет историю и простой 7/30-day trend.

### Навигация и хранилище
- Mobile hotbar + desktop меню ведут в те же разделы.
- Offline-first работает без сети.
- Из профиля доступен экспорт данных.

### Privacy
- Есть экран согласия на health-data.
- Камера запрашивается только при явном действии.
- Политика обработки health-данных документирована.
